# 技术讲解视频制作

制作可播放、可编辑、可追溯的技术图解视频。先读项目已有的 AGENTS.md / CLAUDE.md、制作文件和当前进度，确认本轮阶段；目录为空时使用 init 创建四份制作文件，缺少项目指令文件不构成阻塞。保留已有确认与音视频，不自动重做已验收环节。本 skill 不授权发布、提交 Git、删除云端音色或上传本人录音。

## 配音风格强约束

- 配音必须采用【技术讲师的讲解风格】：面向正在学习的听众，主动引导理解；描述现象、举例、定义概念、解释因果、区分概念和纠正误解，要读出相应的层次、重音与停连。发挥已选讲师音色的讲解特点。
- 【自然】指讲课表达自然、亲切、清楚，不得解释为同事闲聊、朋友聊天、随口叙述或整篇平顺念稿。避免播音腔、广告腔和朗诵感，不等于去掉讲师感；正常语速不等于语调平直。
- 读法规则须从具体原句写清听众目标、积极有把握的精神状态、关键动作/结果/区别的轻重，以及完整意群与局部节奏；禁止只写形容词或用逐段增加停顿代替讲师感。参考音频的证据核对、迁移边界与写法示例见 [references/voice-direction.md](references/voice-direction.md)。
- 必须将讲解设计对应到实际支持的合成控制，并用代表性音频听审验证。仅切换讲师音色、改Markdown或填写未发送的 `direction_notes`，不得宣称已落实讲师风格。没有听审证据时明确标记待听审；完整执行见 [references/voice-direction.md](references/voice-direction.md)。

## 画面动画强约束

- 画面演出过程，不摆出结论：每句旁白找出动词，落成可见的状态变化；标签和批注只补充，不代替动作。关掉声音只看画面，也应能大致看懂。
- 全片沿用一个舞台和固定角色，关键物体（如一条约束）始终是同一个对象；不按句清屏重画相同构图，相邻镜头只换框内文字视为模板化。
- 讲解中超过2秒的静止段全片不超过3处；动作锚定到关键词的真实时间，使用缓动、预备、手绘描画与交错进场，不用全局抖动制造运动。
- 每条片子标出1～2个名场面，先做15～30秒样片确认再铺开。方法与动作分镜格式见 [references/animation.md](references/animation.md)。
- 先定隐喻再画：不沿用以前其他视频的布局和角色；同一条视频内，后一幕默认延续前一幕已建立的舞台、角色和关键物体，换舞台须交代关系。画面要饱满（主体占画面一半以上、开场1秒内出现），角色全程在场。角色可卡通化，但只表现它真实具备的状态。已定稿的方向与完整示范见 `assets/examples/window-overflow/`，组件库与命令见 [references/animation-kit.md](references/animation-kit.md)。
- 箭头、连线必须声明指向对象（`target`），终点落在该对象上、不压字；箭头和移动物件要抽出现、完全显示、与相邻物件同屏、消失的帧，不只抽关键词那一帧。
- 导出前必须生成关键帧联系表、亲眼查看，并按 animation.md 第7节的失败清单逐项自审；静止段超标只能补与旁白对应的动作，不能加闪烁、细线或放宽检测来通过。

## 默认配置与适用边界

- 中文技术讲解，默认MiniMax `speech-2.8-hd`，音色 `Chinese_casual_instructor_nv1`，正常语速 `speed=1`，凭据 `MINIMAX_TOKEN_PLAN`。
- 音量后期 +6dB，峰值限制 -1dBFS；这是当前偏好，不是所有输入都适用的响度标准。按实际音源检查。
- 手绘白板，1920×1080、30fps、文楷字体；图形为主、极淡纸纹，无点阵、无斜纹阴影。橙色动作、蓝色返回，一次最多一条批注；字幕默认50px，尾部不带标点。
- 画面右上角不放文字；左上角使用「作者 / 本节技术要点」，作者通过project.json配置，本账号默认「程序员青戈」。斜杠后写具体技术内容，例如「上下文窗口、压缩与指令遗漏」，不使用泛泛的「编程图解」或只写「上下文」。新主题须同步更新模板页眉。
- 音色、表达、停顿、画面和输出规格可按当前任务调整。示范样片（`assets/examples/`）与历史网页请求案例只作对照，不是后续视频的固定内容或构图。
- 本账号正式成片至少3分钟，以实际音轨计算；不能靠放慢语速或堆静音凑时长。16秒验收案例只用于离线研究模板，不作为新视频时长标准。
- 新制作不再使用豆包。旧片、历史音频与demo保留原配置，不因默认改变自动重合成。MiniMax适配及实际验证范围见 [references/production.md](references/production.md)。

## 工作流程

**文稿确认 → 读法与设置 → 试听确认 → 全文音频与真实时间 → 字幕与分镜 → 样片确认 → 整片制作、自审与导出。**

阶段产物、确认条件与前置变更后的重建范围见 [workflow.md](references/workflow.md)。第一次推进制作或前置内容改变时读取；不重做已有验收，不把技术检查当用户确认。

编写、打磨或审核口播稿时，读取 [script-review.md](references/script-review.md)：核对机制解释、可观察的例子、适合听的表达，以及修复复核和独立盲审的区别。按本轮授权选择审查范围，不默认增加审核轮数。

### 阶段结束时主动询问

- 试听交付后主动询问是否合格、是否沿用生成全文；已有明确确认直接沿用。
- 完整分镜与主代理自查完成后主动询问是否需要独立审核；选择落实后再进动画。已有本轮审核授权或免审核决定直接沿用。
- 用户未回复不等于通过。模型、档位与只读审核范围按用户约定。

## 配套工具

先读 [production.md](references/production.md)。新主题只有一条默认技术路径：`pipeline.py init/audio/timeline` → explain-kit 页面 → `video.mjs preview/check/render`。具体数据协议和章节写法见 [project-protocol.md](references/project-protocol.md)。

- `init` 默认生成通用空白舞台和制作文件；作者与主题写在 `project.json`，不预设三列六步或纸卷隐喻。
- `audio` 负责合成与缓存，调用须在用户授权内；`timeline` 负责真实词锚点、章节和同源 JSON/SRT，拒绝过期音轨。
- `scene.mjs stills/lint/video` 是样片与整片共用的抽帧、画面检查和渲染底座；`video.mjs` 补充整片时长、同步、跳转、资源和项目因果检查。整片和样片都必须先自审。
- `scenes.js` 只实现本片画面，按时间纯函数绘制；不是再写一套渲染、播放和检查脚本。主题特有因果通过时间约束及 `audit` 检查，不把网页请求事件写进通用工具。
- `sync_skill.py` 比较源版与安装版，应用时备份差异，不删除目标独有文件；同步后再检查摘要。工作目录是本项目时，唯一源版为 `技能/video-explain/`，安装目录不是并行源版。
- 历史网页请求模板、豆包与 `--demo` 仅作兼容，见 [legacy.md](references/legacy.md)；不作为新片默认入口。

脚本负责稳定机制；叙事、隐喻与动作由当前任务设计。字幕从同一真实时间源生成，页面只读取；不改生成文件掩盖同步问题。

## 迭代原则

后续根据真实制作中出现的问题改进本 skill 与模板。先修复可复现的问题，再沉淀适用规则；不要把一个案例的停顿、分段数量或业务结构写成通用要求。保留已验收视频作为基线；未经要求不重新合成它、替换成片或扩大清理范围。
