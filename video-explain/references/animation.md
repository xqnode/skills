# 讲解动画方法

设计分镜、写页面动画和审片时读取。目标：画面演出过程，而不是摆出结论。关掉声音只看画面，观众也应能大致猜出发生了什么。组件与命令见 [animation-kit.md](animation-kit.md)，已验收的完整示范见 `assets/examples/window-overflow/`（`contact.png` 是好的，`bad-v2-contact.png` 是同一段的反面案例，说明见 `反面案例说明.md`）。开始设计前先把两张联系表都看一遍。

## 0. 先定隐喻，再定布局

- 先回答：这个概念像现实里的什么东西？把核心关系变成一个能动的物体。例如「上下文窗口」= 一条聊天纸卷从一个固定的取景框下面走过：框里是模型看得到的，框外压暗；截断就是纸卷左推。这样「模型看不到」和「界面里还在」由同一个物体同时表达，不需要再画左侧面板和回收区。
- 好隐喻的标准：关键结论在画面里是物体之间的位置关系，而不是文字标签；一个物体承担多个事实。
- 独立设计指不沿用**以前其他视频**的布局、角色和配色当默认值；旧片只作对比，不作模板。设计前至少比较两个隐喻，选能把核心因果放进同一画面的那个。
- **同一条视频内要延续**：上一幕已经建立的舞台、角色和关键物体，下一幕默认沿用。只有讲的机制在结构上真正不同才换舞台，换的时候要交代与上一幕的关系（例如摘要做完后要放回上下文窗口，而不是让窗口从画面上消失）。做中间某一幕前，先看前一幕的页面或联系表。
- 角色可以卡通化，观众接受度高：圆润、表情友好、有明确动作（趴在框上往里看、有新内容时弹一下）。避免通用方框机器人和单独悬浮的大眼睛（压迫、吓人）。
- 角色只表现它真实具备的状态：模型不知道自己少看了什么，就不要给它问号、困惑或「发现缺失」的表情；给观众的提示用旁注表达。
- 表达「缺失」：在容器里本该有的位置画一个空位（`emptySlot`），写明缺的是什么；不要把缺失的东西本身画进容器——画在框里就会被读成「它还在里面」。原物如果还存在于别处（例如聊天记录），就画在它真实所在的位置。

## 1. 先找动词，再画画面

逐句圈出旁白里的动词（装入、挤出、丢掉、压缩、发送、命中、淹没、带回），这些就是主动作；名词只是道具。每句话至少落到一个可见的状态变化上。

| 旁白 | 摆结论（避免） | 演过程（采用） |
| --- | --- | --- |
| 窗口满了，较早的对话被截掉 | 一个框加「容量有上限」标签 | 纸片逐张落到纸卷上、容量条上涨；超出部分伸出框外；纸卷左推，最早的纸片移出框外但仍在纸卷上 |
| 摘要会漏掉约束 | 漏斗图标加红叉 | 多张卡片推进漏斗，出口只剩两张，约束卡在漏斗里被揉掉 |
| 模型对中间内容利用得差 | 三个框分别写开头、中间、结尾 | 同一张卡片依次放到三个位置，注意力光照扫过，中间段明显变暗 |

标题、标签和批注只补充画面说不清的部分，不能代替动作。

## 2. 一个舞台，固定角色

- 全片（或一个大段落）沿用同一套舞台和角色，例如「聊天记录」「上下文窗口」「AI」。不按句子清屏重画三个框。
- 贯穿全片的关键物体保持为同一个对象：它被写下、被装入、被挤出、被找回，观众跟着它的命运理解因果。
- 换话题用镜头推进、平移或局部放大转场，例如推进窗口内部讲 token；只有真正换舞台时才整体淡出。
- 相邻 3 个以上镜头构图几乎相同、只换框内文字时，视为模板化，需要改成同一舞台上的状态变化。
- **画面饱满**：主体物件占画面高度的一半以上（大约 y 200～950 之间的主要区域），不要只用上半部分、下方大片空白；开场 1 秒内主体就要出现，不要先放一段空画面。
- **角色全程在场**：角色是主角，从开场就在舞台上，用视线、弹跳、转头跟着内容走；不要只在最后几秒出现。

## 3. 画面不能整段停住

| 层级 | 作用 | 示例 |
| --- | --- | --- |
| 主动作 | 对应当前那句旁白 | 卡片被挤出、请求沿路径发出 |
| 引导动作 | 把视线带到重点 | 描线箭头、高亮笔划、局部放大、圈出 |
| 呼吸层 | 防止画面死掉，幅度小、速度慢 | 水位轻微起伏、光标闪烁、角色眨眼 |

- 讲解中超过 2 秒无任何变化的段落，全片不超过 3 处，且只放在有意的停顿或总结处。
- 呼吸层不能代替主动作，也不要做成全局抖动：线条和文字保持稳定，不用持续的滤镜抖动。
- 静止检测只说明画面有变化，不说明动作在讲解内容；仍需看关键帧和成片。

**静止段超标时怎么补（防钻空子）**：回到动作分镜，找出那段旁白在说什么，补一个讲它的动作，并在检查记录里写明「哪一秒、哪句旁白、补了什么动作」。以下做法不算解决：

- 加闪烁、眨眼、光标、持续抖动等只为制造像素变化的呼吸层；
- 只加细线描画、小图标位移（检测不到，也说明观众注意不到）；
- 加和旁白无关的装饰运动，或提前出现后面才讲的结果；
- 放宽检测阈值或改规则让它通过。

可用的有效手段：与旁白对应的大面积洗色（`sheet` 的 `wash`、`pulse`）、扫描带、量出长度、计数增长、内容逐行写出、对象靠近/弹出/跳入等。

## 4. 节奏对准关键词

- 用真实字/词时间，把动作锚到关键词出现的时刻，例如念到「挤」才挤出；不要整句开头一次性摆出全部元素。
- 一句话可以有 2～3 个动作节拍；句间留 0.3～0.5 秒让画面落定。
- 结果不早于导致它的动作结束；预告性提示可以提前出现，但不剧透结果。

## 5. 动作质感

- 缓动：出现用轻微回弹，移出用加速，停靠用减速；不用匀速直线。
- 预备：大动作前先反向收一下，例如被挤出前先往里缩，让观众提前把视线移过去。
- 手绘动势：线条边画边出现，文字逐字写出，划掉用笔真实划一道，圈出用笔画绕圈。
- 交错：同组元素间隔约 80～150ms 依次进场，避免整块同时出现。
- 所有动画是 `renderAt(t)` 的纯函数，可任意跳转复现，不用随机数或独立 CSS 动画决定状态。

## 6. 名场面优先

每条片子挑 1～2 个回答核心问题的场景做重，投入约 40% 的画面制作时间，其余镜头可以简洁。名场面在分镜里单独标注，并先做 15～30 秒样片给用户确认，再铺开整片。

## 7. 自审循环（导出前必做）

1. `node scene.mjs stills --page <页面> --every 2` 生成关键帧与联系表；每个关键词再用 `--times` 抽前、中、后三帧（例如关键词 12.3 秒抽 12.0,12.5,13.2）。
2. 运行 `node scene.mjs lint --page <页面>` 做自动画面检查，先把错误清零；警告逐条判断，在自审里说明保留理由或改掉。
3. 必须实际打开联系表和至少 4 张 1080p 原尺寸单帧查看（不能只读代码或数据）。自动检查查不到的（隐喻、因果、时序、连贯、边框相接）靠这一步。对有边框、容量条或飞入物件的说明区，覆盖出现、执行、返回、移动和落定状态；不能只抽主角或最终结果。逐张检查字与线、字与卡片的净距，不能只确认「没有重叠」。
4. 复制 `assets/explain-kit/自审模板.md` 为样片目录的 `自审.md`，对照下面的失败清单逐项写结论和依据；不通过的先改，再重新生成关键帧、重新自审，直到全部通过。「时序」必须逐个关键词核对，不能只凭分镜设计。
5. 导出 MP4：`scene.mjs video` 先检查 `自审.md`，再跑自动画面检查，任一不合格都拒绝导出；导出后自动统计静止段，不通过按第 3 节补动作，导出新版本，不覆盖旧版。
6. 有条件时派独立审片（只给材料，不给自己的问题清单），合并意见后再交给用户。审片判断遮挡时注意区分静止遮挡和移动中经过（扫描带、飞入的卡片），单张截图不足以定论。

**失败清单**

| 类别 | 不通过的情况 |
| --- | --- |
| 因果 | 关掉声音看不出这段在讲什么；画面意思和旁白相反（例如旁白说「没聊多少轮」画面却计数暴涨） |
| 时序 | 结果、摘要内容、结论早于对应关键词出现；演示后又撤回，让观众分不清最终状态 |
| 事实 | 把「可能/如果」画成「必然」；把常见实现写成规定；角色表现出它不可能知道的事；把缺失的东西画进容器（应改为空位） |
| 构图 | 相邻镜头构图相同只换文字；大片空白而另一侧拥挤；主体只占画面上半部分；开场空白超过 1 秒；角色不在场；强调元素落在与其含义相反的位置（「不在窗口里」的卡片压在窗口上）；同一条视频里无交代地换掉上一幕的舞台 |
| 遮挡 | 文字与图形或其他文字重叠（包括洗色条、高亮条压住文字、细边框擦过字形）；内容进入右上角或字幕区（y>950）。**必须逐张看原尺寸单帧判断，联系表缩略图不算**；依据里写出逐张查过的帧名。自动检查可能漏掉细线、先画的物件和短暂擦字，零错误不能代替人工复核 |
| 接触 | 表示压、夹、推、接住、放入的物体和被作用的对象之间留着空隙（压板悬在纸堆旁、夹具没夹住、卡片没落进槽）；动作结束时两者没贴合。每个这类动作抽开始、中间、结束三帧原尺寸核对 |
| 指向 | 箭头、连线、批注的终点没落在要指的对象上（指到空白、容器边或别的对象）；箭头头部或连线压字；指向对象还没出现或已经消失时箭头仍在 |
| 可读性 | 正文小于 22px；说明文字用浅灰 `muted` 而非 `sub`；橙色说明文字小于 26px 或未用 `orangeD`；淡出后仍残留在画面上的低透明度文字；说明字紧贴进度条、无关边框或相邻标签，虽未相交仍显拥挤 |
| 风格 | 全局抖动；点阵、斜纹阴影；颜色语义混乱（橙=动作/问题，蓝=返回/保留） |
| 字幕 | 尾部带句号、逗号、问号等句末标点；删掉了引用原话的「」（要对照稿子补回；在句尾时 」 也保留，例如 `却没有保留「不要引入新依赖」`） |

**净距按字形量，不按坐标猜。** SVG 的 `y` 通常是文字基线，基线离进度条 30px 不代表字顶有 30px 空白。普通说明文字与相邻进度条或无关边框可先留约一字高的净距，再看最终播放尺寸调整；例如 24px 文字先按约 24px 空白安排。这是布局起点，不是全场景硬阈值；卡片内部标题、明确的连线标注按所属关系安排。修复时一起看相邻标签与运动路径，避免挪开一处又贴住另一处。用户指出的问题必须补抽该时刻及前后状态，更新自审依据；不能用「移动中经过」解释持续挡字或过密布局。

## 动作分镜格式

在 `画面要求.md` 或项目分镜文件中，每句旁白至少写：

| 字段 | 内容 |
| --- | --- |
| 旁白 | 原句或段 ID |
| 主动作 | 动词加对象，例如「约束卡被挤出窗口」 |
| 锚点 | 触发关键词与 `start`/`end` |
| 角色 | 涉及的固定舞台对象 |
| 引导/呼吸 | 本句的次要运动 |
| 完成状态 | 动作结束后画面应保持的样子 |

先审动作分镜，再写 HTML。审分镜时逐句问：去掉字幕，这一句的画面变化能否说明它在讲什么？
