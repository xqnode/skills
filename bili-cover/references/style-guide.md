## 可复用的品牌识别

**固定识别：**
- 默认白色为主背景，黑色粗体标题，单一强调色；选择 `#纸面原型` 时允许米白纸底、中央浅灰方格和淡黄色强调。
- 作者署名写作「程序员青戈」，位于中央4:3安全区顶部，字级低于主标题；中间两行大字依次为主技术栈（通常1–3个）与系统中文名称，下方为小字技术栈标签。详见 [默认信息层级](../SKILL.md#默认信息层级)。
- 文字、图标和标签都按中央4:3安全区排版。

**每期可变：**
- 根据主题选择居中、左对齐、流程图或对比版式。
- 使用一项最能代表项目的真实视觉线索；没有合适素材时保持纯文字。
- 每期强调色由用户当次指定优先。用户没有指定时，可沿用同一课程系列已选的颜色。

## 风格标签

新做封面且用户没有指定风格时，先询问偏好的标签；根据标题和题材选出 3–5 个最合适的标签供选，完整风格库如下。可以组合一个主标签和一个辅助标签。用户指定风格或只要求修改现有封面时直接执行，不重复提问。

| 标签 | 构图方向 | 适用情况与边界 |
| --- | --- | --- |
| `#大字主视觉` | 主标题占中心，黑色粗体配一个关键词色，署名和技术标签简洁 | 技术入门、主题概览；减少装饰，不做每次居中同构 |
| `#杂志编辑` | 不对称编辑网格，左对齐标题、留白、细分隔线、局部强调词 | 入门教程、专题讲解；保持纯白，避免大块衬底色和斜向粗色块 |
| `#轻界面卡片` | 标题与淡灰细线卡片/窗口轮廓组合，少量主题色 | 工具或框架教程；不伪造可读界面，不铺成右侧图案背景 |
| `#项目实景` | 用用户提供的真实项目画面做一处小型视觉证据，标题仍清晰优先 | 项目实战；没有真实截图时不用假UI代替，可退回纯文字构图 |
| `#系统蓝图` | 少量节点与连线表达组件关系，背景仍为纯白 | 架构或技术栈讲解；图形仅作稀疏示意，不做满版纹样或右侧装饰墙 |
| `#左右对照` | 安全区内两个简明区域并列，靠标题/短标签区分 | 方案选型、前后对比、常见错误；内容少、字号大，不延伸到外侧裁切缓冲 |
| `#纸面原型` | 米白方格纸、黑色大字、淡黄色标记、一处简洁线框示意 | 用户认可的可选方向，适合技术入门、接口教程与项目实战；细则见 [纸面原型](paper-prototype.md) |

这些标签只用于选择封面方向，不得作为额外文字印在图片上。默认偏好仍为纯白背景，并避免右侧图案化装饰；`#纸面原型` 使用已认可的米白方格纸分支，不把这一选择强制应用于其他风格。

署名目前按文字处理。只有用户提供了正式Logo或明确要求图标时，才放对应图形；不临时编造固定吉祥物或新Logo。

## 四种版式方向

先判断视频重点，再选一种布局；例子说明可选构图，不要求每期更换，也不取代4:3安全区。

| 视频内容 | 版式 | 构图要点 |
| --- | --- | --- |
| 课程主题或技术栈总览 | 大字标题型（默认） | 主标题占主要视觉面积；署名、标签、技术词做轻量辅助。 |
| 从零开发完整项目 | 项目成果型 | 重点展示真实运行结果或用户提供的项目画面；标题仍最大，截图/界面作为证据。没有真实素材时用简单抽象图形，不能伪造可读UI截图。 |
| Agent、RAG、部署或系统结构 | 流程/架构型 | 画3–4个关键节点或阶段，控制节点文字数量；流程图服务于标题，不能挤占安全区或变成小字说明书。 |
| 报错排查、优化前后、方案选择 | 对比型 | 在中央4:3区内分成左右或上下两个清楚区域，每侧用短标签表达差别；4:3预览时两侧内容都要完整。 |

主题元素应帮助观众迅速判断“这期讲什么”。按本期需要选择一个视觉重点；插图、代码符号和技术词都不需要每张齐备。

## 标题与缩略图层级

- 主标题表达本期核心项目或学习结果，优先于装饰和辅助词。
- 一张图最多设两级主要文字：主标题；标签/技术项作为辅助。确有内容需要时可再加一行副标题，但保持清楚层次。
- 让视频标题提供上下文、封面突出核心主题。用户明确给出封面原文时按其文字与分行执行；建议删减时先给方案，不擅自删改。
- 第一行主技术栈通常为1–3个；下方标签是辅助层，数量不受主技术栈数量限制。用户给出的全部标签须保留，较多时分成两行或调整字号与间距，不自行删减，不把标签做成第三行大标题。
- 检查320×240预览时，主标题应先读到；作者名、徽标与装饰不能更抢眼。若文字挤在一起，先简化辅助层或调整分行，再考虑缩小整个内容组；继续遵守4:3裁切范围。
